Metronautica: Navigate wearable triaxial accelerometer signals into transparent metrology and reports.

Description

Native wearable triaxial accelerometer parsing, signal diagnostics, clipping, static and dynamic characterisation, filtering and reporting. Developed for the wearable-accelerometer metrology research article under submission for publication; the associated analyses and data are available in WAM: https://github.com/miltheo/wam.

Details

The package provides functions for native decoding, common-format acceleration data, signal diagnostics and selected assessments. Each function documents its input, returned quantities, units and processing settings. implementation-guide maps the workflow to the public functions.

Repositories

Package source: https://github.com/miltheo/metronautica. WAM analyses, observations and native-recording catalogue: https://github.com/miltheo/wam. Native recording payloads are separate release attachments.

Start here

getting-started provides a complete offline example; native-recording-examples covers stationary and ten-stage orbital-shaker recordings.

Standalone counts

The published-filter and custom-cutoff count function accel_metric_agcounts is documented separately. The AG selector is disabled in compute_accel_summaries. GT3X parsing defaults to native precision, with an explicit legacy_3dp mode.

Scope

Functions calculate features and metrological outcomes for supplied recordings and selected intervals. Cohort-level inference and inter-device equivalence testing are provided by the linked WAM analyses. Calibration, filtering and analysis settings are explicit caller choices. Dynamic clipping requires explicit stepped-RPM schedule parameters; the native-recording example supplies ten six-minute stages from 50 to 500 RPM.

Workflow

Load a sample or supply a recording, call parse_raw_auto, inspect metadata and diagnostics, select the intended interval, then call the required metrology or feature functions. Use static_1hz_means, static_drift, static_allan and the direct accel_metric_* functions when individual outcomes are needed. Static_metrology_from_tbl and dynamic_metrology_report remain optional combined assessments.

Compute ActiGraph-compatible or modified activity counts

Description

Standalone activity-count calculation with the published coefficient-defined ActiGraph filter by default, explicit custom bandpass cutoffs, and auditable treatment of missing samples and boundaries.

Usage

accel_metric_agcounts(tbl, epoch_s = 1, fs_hz,
    lower_hz = NULL, upper_hz = NULL, filter_order = 4,
    lfe = FALSE, gap_policy = c("error", "zero", "carry_forward"),
    vm_round = TRUE, start_time = NULL, end_time = NULL,
    boundary = c("error", "pad"), pad_value = NULL,
    filter_guard_s = 60)

Arguments

tbl

Common-format data frame/tibble, parser bundle with data, or clip bundle with full. Required columns are POSIXct time and finite numeric ax_g, ay_g, az_g in g. Rows must be strictly time ordered on the supplied nominal sampling grid. Observed zero-valued samples are retained as observations.

epoch_s

Positive whole epoch duration in seconds. Axis counts are accumulated first; vector magnitude is calculated afterwards. Incomplete trailing raw epochs are discarded before rate conversion and the discarded sample count is recorded.

fs_hz

Nominal recording frequency in Hz, supplied explicitly. Supported rates are 30, 40, 50, 60, 70, 80, 90, 100, 32, 64, 128 and 256 Hz. A frequency estimated across recording gaps is not a substitute for the acquisition setting.

lower_hz, upper_hz

Both NULL retain the exact published filter coefficients; a nominal cutoff pair is not substituted for that response. Supplying both selects a modified causal Butterworth bandpass. These custom frequencies are the lower and upper -3-dB points, satisfying 0 < lower_hz < upper_hz < min(15, fs_hz/2). The historical internal processing rate is 30 Hz.

filter_order

Butterworth prototype order, integer 1 to 8; the bandpass transfer function has twice this order. Default 4. Ignored for the published filter, whose coefficient-defined order remains unchanged. Numerically unstable custom designs are rejected. Custom peak gain is matched to the published filter; subsequent historical scaling and count operations are retained.

lfe

FALSE uses the Normal-filter threshold rule: rectify, suppress values below 4, saturate at 128 and floor. TRUE selects the published low-frequency-extension threshold rule: suppress values below 1, use floor(value)-1 for 1 <= value < 4, and otherwise floor after saturation at 128. This changes the threshold rule, not the bandpass coefficients. Available real-data AGD validation used FALSE.

gap_policy

Default error rejects unobserved interior sample positions. zero inserts zero acceleration, while carry_forward repeats the last observed triaxial sample. These are explicit computational conventions, not evidence of the missing physical acceleration. NA/Inf axis values are rejected, not automatically reinterpreted as gaps.

vm_round

TRUE rounds sqrt(Axis1 squared + Axis2 squared + Axis3 squared) to the nearest integer, as in the R comparison implementation. FALSE retains the unrounded vector magnitude. Summing one-second vector magnitudes is not equivalent to accumulating axes before taking their magnitude.

start_time, end_time

Optional single POSIXct interval bounds; start is inclusive and end exclusive. Defaults are the first supplied sample and one nominal sample interval after the last. Epochs start at the resolved start_time, without implicit rounding to a civil-clock boundary. Native recording start and first observed sample are recorded separately when parser metadata is available. Process a continuous interval before selecting derived epochs when filter history is required.

boundary

Default error rejects requested bounds extending beyond observed coverage. pad permits only explicitly requested leading/trailing sample padding, with pad_value required. The function never automatically extends to a native header's start/stop time. Padding does not establish vendor compatibility.

pad_value

Three finite acceleration values in g for X, Y, Z, used only with boundary = "pad". Both requested ends use these explicit values. The number and location of padded samples are reported. No constant-first-sample startup padding is inserted implicitly.

filter_guard_s

Non-negative flagging interval after an imputed sample or initialisation, default 60 seconds. Power-of-two conversion additionally flags the preceding second around imputation and the final second of finite-record processing because its FIR stage is centred. This changes flags only, not counts. It is a user-selected processing-context guard, not a validated settling-time guarantee or measurement uncertainty bound; very low custom cutoffs can require a longer guard.

Details

The published path converts each axis to 30 Hz using the rate-specific historical method, including the separate power-of-two path; rounds the converted acceleration to three decimals; applies the coefficient-defined causal filter with steady-state initialisation; rescales by (3/4096)/(2.6/256) times 237.5; rectifies, thresholds, saturates and quantises; averages and floors groups of three samples to 10 Hz; then accumulates epochs. Published finite-record behaviour of the power-of-two converter is retained. Custom filtering replaces only the bandpass stage. It is identified as modified counts and does not inherit validation of published behavioural thresholds.

The implementation uses supplied acceleration precision without reconstructing discarded digits. For GT3X inputs, parse_raw_auto uses native precision by default; precision = "legacy_3dp" explicitly retains the earlier read.gt3x rounded conversion. A manually rounded table remains rounded. Source timestamps and gaps are not repaired by parsing.

This function is available separately from compute_accel_summaries. The AG selector remains disabled, so existing summary pipelines are not silently changed. Neither agcounts nor Python is a runtime dependency.

Value

A tibble with time, Axis1 (input Y), Axis2 (input X), Axis3 (input Z), Vector.Magnitude and value (the same vector magnitude). Additional columns input_samples, missing_samples and padded_samples count nominal positions within each output epoch. imputed identifies epochs containing inserted values; affected_by_imputation also includes the filter guard; boundary_affected identifies initialisation/finite-record context. These flags describe insertions by this count call, not values imputed before input was supplied. Counts are not replaced by NA when an explicit fill policy is chosen: inspect these flags before interpretation. The settings attribute records the reference, exact coefficients, filter choice, precision provenance where available, interval, gaps, padding, discarded samples, rounding and quality conventions.

Validation scope

The original experiment included 89 native/AGD recording pairs: 45 static recordings tested in three 30-minute windows each and 44 secondary-shaker recordings over available raw coverage. The default matched the pinned official Python calculation exactly for 3,763,659 paired one-second axis values. Exact ActiLife export reproduction additionally depended on native precision, startup context and missing-sample conventions; it was not universal across all recording transitions. This is calculation validation, not validation of device interchangeability or behavioural thresholds. The package documentation includes the full agreement and coverage tables.

Implementation

Implemented in R/m_agcounts.R. Standalone count calculation.

References

Neishabouri et al. (2022). Quantification of acceleration as activity counts in ActiGraph wearable. Scientific Reports 12, 11958. doi:10.1038/s41598-022-16003-x.

Published coefficients: ActiGraph/agcounts, GPL-3.0, commit 3137c9b9a26539ae2d9645d396586fe15faece59. https://github.com/actigraph/agcounts. Numerical coefficients are acknowledged from that source; the R implementation is provided by Metronautica.

Compute Activity Index

Description

Compute Activity Index.

Usage

accel_metric_ai(tbl, epoch_s, fs_hz, anchor = "center", ai_noise_var
    = NULL, ai_noise_mode = c("supplied", "window_start",
    "quiet_segments"),
    ai_noise_window_s = 30, ai_quiet_quantile = 0.1, ai_scale =
    c("absolute", "relative"), ai_epoch_summary = c("sum", "mean"))

Arguments

tbl

Acceleration data frame/tibble with POSIXct time and numeric ax_g, ay_g, az_g in g, or a parser/clip bundle containing data/full. Input conversion preserves values and metadata.

epoch_s

Positive output-epoch duration in seconds. Samples are grouped by elapsed time from the first sample; the final partial epoch is retained. Different epoch lengths define different processing pipelines.

fs_hz

Sampling frequency in Hz. Used to convert durations to sample windows or sums to time integrals. Supply one finite positive scalar. A NULL estimate is available only where shown in Usage.

anchor

Output timestamp selected from the one-second bin starts: first for start, last for end, or the middle bin start (ceiling of half the bin count) for center. This differs from sample-level anchors of ENMO/MAD and does not change the calculated values.

ai_noise_var

Mean per-axis stationary noise variance in g squared. Required by default when AI is requested; estimate with compute_ai_noise_var_from_static. An explicit zero requests no noise subtraction.

ai_noise_mode

Default supplied requires ai_noise_var. Explicit window_start or quiet_segments opts into estimation when ai_noise_var is NULL. The initial window must be stationary; quiet selection does not establish stationarity. Failed estimation errors rather than substituting zero. A supplied variance takes precedence.

ai_noise_window_s

Initial noise-window duration in seconds; used only for window_start estimation.

ai_quiet_quantile

Quantile strictly between zero and one for quiet_segments selection.

ai_scale

Absolute Activity Index in g (default) or dimensionless noise-relative Activity Index.

ai_epoch_summary

Sum (default) or mean of the one-second Activity Index values within each output epoch.

Details

Calculate sample variance per axis within one-second windows, average the three variances, subtract the stationary mean-axis noise variance, truncate negative excess to zero and take the square root. The absolute index is in g. Relative scaling divides excess variance by noise variance before the square root; zero noise variance gives undefined relative values. Aggregate the one-second indices by the selected sum or mean. See measurement-definitions for calculation definitions. No additional device calibration is performed by choosing a feature.

Value

A tibble with epoch_id, time and value. Absolute output is in g; relative output is dimensionless. Sum and mean refer to the one-second indices, not acceleration samples. Timestamps select the first, last or middle one-second bin start within each output epoch. The settings attribute records noise variance/source, estimation settings, scale, aggregation, rate and duration; ai_noise_var_used also records the variance in g squared.

Implementation

Implemented by accel_metric_ai in R/m_accel_summary_suite.R. See implementation-guide for the framework and function map.

References

Bai et al. (2016), doi:10.1371/journal.pone.0160644.

Compute MIMS-unit

Description

Compute MIMS-unit.

Usage

accel_metric_mims(tbl, epoch_s, dynamic_range_g, mims_filter_type =
    "butter", mims_cutoffs = c(0.2, 5), mims_use_extrapolation =
    TRUE, mims_use_filtering = TRUE, mims_combination = "sum",
    mims_allow_truncation = TRUE)

Arguments

tbl

Acceleration data frame/tibble with POSIXct time and numeric ax_g, ay_g, az_g in g, or a parser/clip bundle containing data/full. Input conversion preserves values and metadata.

epoch_s

Positive epoch duration in seconds, passed as the upstream MIMS epoch setting. MIMSunit controls epoch boundaries, timestamps and treatment of partial epochs; this helper does not impose the common elapsed-sample epoch index.

dynamic_range_g

Peak-to-peak configured axis measurement span in g: 16 means -8 to +8 g. The summary function uses valid acquisition metadata when NULL; MIMS fails if neither is available. The direct MIMS function requires this argument. No range is inferred from observed values.

mims_filter_type

Filter family passed to MIMSunit::custom_mims_unit: butter (default), ellip or bessel as supported upstream. Its interpretation belongs to that implementation; select together with mims_cutoffs.

mims_cutoffs

Filter cutoffs in Hz; default c(0.2, 5). Use c(0.2, 10) explicitly for the altered passband.

mims_use_extrapolation

Logical passed to MIMSunit. TRUE enables its saturation/extrapolation step; FALSE skips that step while the upstream algorithm still interpolates to its processing grid. Does not mean extrapolating behavioural time.

mims_use_filtering

Logical; enable the specified internal MIMS band-pass processing. FALSE bypasses that internal filter, creating a different feature pipeline.

mims_combination

Axis-combination method passed to MIMSunit: sum adds axis summaries; vm combines them as a vector magnitude. The default is sum.

mims_allow_truncation

Logical; permit the upstream MIMS implementation to set sufficiently small summary values to zero. This is an algorithmic small-value operation, not clipping native recordings.

Details

Call MIMSunit::custom_mims_unit with triaxial g inputs, configured axis limits and the selected internal processing. Retain its timestamps and combined MIMS output. Default 0.2-5 Hz and explicit altered 0.2-10 Hz are different pipelines; resolved settings and dependency version are returned. See measurement-definitions for calculation definitions. No additional device calibration is performed by choosing a feature.

Value

A tibble with time (upstream MIMS epoch labels), epoch_id (sequential row number), and value (the combined MIMS-unit output per epoch). These values are not g or mg. The settings attribute records measurement span/limits, filter and cutoffs, extrapolation, truncation, combination, duration and MIMSunit version. Upstream epoch boundaries and partial-epoch handling are retained.

Implementation

Implemented by accel_metric_mims in R/m_accel_summary_suite.R. See implementation-guide for the framework and function map.

Description

Compute dynamic body acceleration.

Usage

accel_metric_odba(tbl, epoch_s, fs_hz, anchor = "center", output =
    c("ODBA", "VEDBA", "PDBA"), static_dynamic_method =
    c("centered_running_mean", "low_pass_static_filter",
    "high_pass_dynamic_filter"), stroke_window_rule = c("fixed_3s",
    "custom_window_s", "stroke_period_1x", "stroke_period_2x",
    "sensitivity_windows"), running_mean_window_s = 3,
    stroke_period_s = NA_real_, lowpass_cutoff_hz = 0.2,
    highpass_cutoff_hz = 0.2, filter_type = "butterworth",
    filter_order = 4, pdba_axes = c("x", "y"), out_unit = c("mg",
    "g"), edge_handling = "partial_centered_window",
    missing_data_policy = "mean_na_rm")

Arguments

tbl

Acceleration data frame/tibble with POSIXct time and numeric ax_g, ay_g, az_g in g, or a parser/clip bundle containing data/full. Input conversion preserves values and metadata.

epoch_s

Positive output-epoch duration in seconds. Samples are grouped by elapsed time from the first sample; the final partial epoch is retained. Different epoch lengths define different processing pipelines.

fs_hz

Sampling frequency in Hz. Used to convert durations to sample windows or sums to time integrals. Supply one finite positive scalar. A NULL estimate is available only where shown in Usage.

anchor

Output timestamp: start selects the first observed sample in an epoch, end the last, and center the middle observed sample (ceiling of half the epoch sample count). This labels the result without changing values.

output

ODBA sums absolute dynamic components across all three axes; VEDBA uses their Euclidean norm; PDBA sums the selected absolute components. Each is averaged within the output epoch.

static_dynamic_method

Axis separation method. centered_running_mean subtracts the centred local axis mean; low_pass_static_filter subtracts a low-pass axis estimate; high_pass_dynamic_filter uses high-pass-filtered axes directly.

stroke_window_rule

Window selection for running-mean separation. fixed_3s uses three seconds; custom_window_s uses running_mean_window_s; stroke_period_1x/2x use max(3, stroke_period_s) or max(3, 2*stroke_period_s). sensitivity_windows uses the requested main window and permits a separate sensitivity summary.

running_mean_window_s

Requested centred averaging-window duration in seconds. Used by custom_window_s and the main result of sensitivity_windows; fixed_3s overrides it. Rounded to samples using fs_hz.

stroke_period_s

Positive representative stroke/movement-cycle period in seconds, required for stroke_period_1x/2x. The function does not estimate a movement period.

lowpass_cutoff_hz

Low-pass cutoff in Hz when static_dynamic_method is low_pass_static_filter. Filter each axis and subtract that static estimate before forming the feature.

highpass_cutoff_hz

High-pass cutoff in Hz when static_dynamic_method is high_pass_dynamic_filter. The filtered axes are the dynamic components.

filter_type

Implementation identifier: butterworth is supported for low-/high-pass separation. This is not an automatic choice among filter families.

filter_order

Order passed to signal::butter for the forward/reverse separation filter. The double-pass frequency response differs from a single pass.

pdba_axes

Axis names selected for PDBA, from x, y and z. Default x/y sums their absolute dynamic components. This option does not change ODBA or VEDBA.

out_unit

Output acceleration unit: mg multiplies the epoch result by 1000; g retains the input scale.

edge_handling

Supported rule partial_centered_window: near signal boundaries, average only the available samples within the centred running window; no external padding is added.

missing_data_policy

Supported rule mean_na_rm: ignore missing observations when calculating local means and epoch means; all-missing estimates remain undefined. This is not gap repair.

Details

Separate static/dynamic axes by the selected implemented method, form ODBA, VEDBA or PDBA, then average within epochs. The centred-window method uses partial available windows at boundaries. A different separation window/filter defines a different pipeline. See measurement-definitions for calculation definitions. No additional device calibration is performed by choosing a feature.

Value

A tibble with time (the selected observed-sample epoch label), epoch_id (integer elapsed-time bin starting at one), and value (g or mg according to the selected output unit).

Implementation

Implemented by accel_metric_odba in R/m_accel_summary_suite.R. See implementation-guide for the framework and function map.

Output settings

The odba_settings attribute records the selected metric, separation method, requested/resolved window duration, cycle-period rule, filter settings, selected axes, output unit and missing-data/edge policies. The direct helper returns one selected metric, not a list of multiple features. The summary function provides separately requested ODBA, VEDBA and PDBA columns.

Acceleration data and metadata contract

Description

The common data format shared by parsing, metrology and feature functions.

Details

An accel_tbl is a tibble with exactly four columns: time (POSIXct), ax_g, ay_g, az_g (numeric acceleration in g, where 1 g corresponds to 9.80665 m/s squared). UTC is the storage convention. No unit inference is performed by the constructor. Preserve acquisition timestamps, gaps and invalid observations until the corresponding diagnostics have been inspected.

Call attach_qc() explicitly to attach diagnostics; parsing through parse_raw_auto() enables QC by default. Parser paths populate available acquisition settings; feature functions resolve a missing rate as documented below. The constructor does not sort or repair the recording. accel_meta() returns the attached metadata. Subsetting externally may retain stale whole-recording QC; recompute it or use the provided clipping functions. Filtering invalidates inherited QC. Feature rate resolution uses an explicit fs_hz, then metadata, then timestamps.

Epoch timestamps and joins

Framework and function map

Description

Connect the public functions, source files and implemented measurement outcomes. Function help documents the resolved parameters; this guide identifies the measurement represented by each stage.

Common data format and signal diagnostics

R/m_parsers.R implements decoding to POSIXct time and triaxial acceleration in g. Stored device coefficients may already be applied during decoding; native does not mean unscaled integer counts. Consult parse_raw_auto for the supported format and validated LEAP scope.

R/m_qc.R implements five post-parse signal diagnostic groups. qc_accel_tbl explains exact numerators, denominators, sequence eligibility and the near-limit threshold. These are operational screening rules, not a sensor acceptance standard. attach_qc stores the results; invalidate_qc removes diagnostics that no longer describe a modified signal.

Static characterisation

R/m_static.R implements static characterisation outcomes. static_1hz_means supplies one-second means; static_drift fits signed g/h slopes; static_offset_vm_5min estimates the specified initial VM offset relative to 1 g. static_axis_noise_metrics separates raw sample SD from the residual SD after linear detrending. The static noise floor is the maximum axis-specific detrended residual SD, not the Activity Index stationary variance.

static_allan uses allan_nonoverlap for non-overlapping cluster means. Its returned axis minima and evaluated averaging times are separate from the maximum across individual axis minima. Supplying a stationary window and assessing environmental stability remain experimental responsibilities.

Dynamic characterisation and calibration

R/m_dynamic.R implements explicit stage selection and VM response calculations. m_dynamic_response fits test VM on reference VM and returns signed bias, response slope/intercept and residual-based errors. The stage normalising span is sqrt(3) times the test-axis peak-to-peak span; the composite denominator is half that span. These operational definitions do not imply that VM occupies the symmetric axis measurement interval.

dynamic_metrology_report reports within-stage epoch-mean VM CV as a fraction. It is not trial-to-trial repeatability CV. Trial aggregation, activation threshold, deadband estimation, inter-device equivalence and Holm-adjusted regional tests are provided by WAM (https://github.com/miltheo/wam). The report's activation/deadband columns are unestimated placeholders.

Reference length matching remains nearest selection on an evenly spaced sample-index grid. Stage-wise and pooled matching are separate. Neither that operation nor diagnostic cross-correlation constitutes timestamp correction. dm_fit_vm_calibration estimates a VM mapping; dm_apply_vm_calibration_tbl applies that mapping and invalidates inherited QC. Independent validation is required to assess benefit outside the fitting recording.

Application-specific features

R/m_accel_summary_suite.R implements time-domain feature definitions and configurable alternatives. The exact operation and unit are given in each accel_metric_* help page. compute_accel_summaries combines requested features and returns resolved pipeline settings.

Epoch duration, sampling treatment, axis filtering, noise correction, calibration state and aggregation are part of a feature pipeline. ENMO truncates negative VM-minus-1-g values per sample; SVMgs variants use absolute differences. MAD is centred within the epoch. ROCAM is a sample-to-sample acceleration-change outcome with no elapsed-time division. The package does not infer physical activity, sleep, energy expenditure or behavioural validity from these features. See feature-comparison for a combined plot over one dynamic recording.

Standalone activity counts

accel_metric_agcounts in R/m_agcounts.R implements the acknowledged published count algorithm and explicit custom-filter alternatives. It operates as a standalone function, outside the summary selector. Report input precision, gap and boundary policies as well as filter/epoch settings; processing flags are not a complete uncertainty budget.

Error and uncertainty reporting

VIM terminology and the cited IEEE sensor terminology/performance standards are used to distinguish measurement quantities and properties. The package returns operational estimates; it does not establish traceability or a complete uncertainty budget by itself. Report the reference, tested range, signal state, sampling/epoch/filter settings, timing diagnostics and units. Residual errors, between-unit variability and uncertainty of a downstream estimate are distinct quantities. See measurement-definitions for the calculation definitions.

Input and return contracts

Raw-signal helpers accept the common four-column acceleration table or data/full bundles; extracting a bundle does not imply selecting, sorting or repairing samples. The table's metadata attribute is authoritative, with top-level meta as a fallback. Calculation helpers generally return a derived result, rather than the original container. Container behaviour depends on the operation: static_clip always returns an acceleration table; clip_dynamic_stages creates a new stage bundle; clip_bundle, QC helpers, filtering and calibration preserve their documented table/bundle form. For a dynamic stage bundle, filter_accel_tbl and clip_bundle modify only the selected full recording, leaving existing stages unchanged. Filter or clip the recording before constructing the stage bundle; do not use the unchanged stages as filtered or newly clipped data. Calibration application explicitly processes the stored stages as well as the full recording.

Derived-input helpers are deliberately different: static_drift and static_offset_vm_5min require one-second means; Allan-minimum/plot functions require an Allan table; allan_nonoverlap requires a numeric axis series; dynamic reporting and fitting require corresponding named stage bundles. m_dynamic_response also accepts numeric VM vectors. Parsers/sample loaders take paths or sample selectors, not acceleration tables. These distinctions follow the quantity each function calculates rather than imposing a common shell API.

Calculation definitions and interpretation

Description

Units, normalisation and implemented arithmetic for the public metrology functions.

Details

Vector magnitude is v=\sqrt{a_x^2+a_y^2+a_z^2} in g.

Signed 1-g VM offset bias

Initial one-second mean VM minus 1 g, averaged over elapsed time up to and including five minutes. This is a VM offset relative to gravity, not a complete axis calibration.

Signed VM drift rate

Ordinary least-squares slope against elapsed hours, g/h. Extrapolation beyond the stationary recording requires an explicitly stated model.

Static noise floor

Maximum axis-specific residual SD after linear detrending over the selected stationary window; reporting in mg requires a factor of 1000. The first-five-minute maximum-axis SD is raw, not detrended. Raw sample SD uses denominator n-1; linearly detrended residual SD uses n-2. Static CV is 100 times SD divided by absolute mean, with a near-zero guard.

Allan deviation

For non-overlapping cluster means \bar{x}_j, \sigma_A=\sqrt{\operatorname{mean}[(\bar{x}_{j+1}-\bar{x}_j)^2]/2}. Cluster duration is in seconds and deviation is in g.

Dynamic response and signed VM bias

OLS of test VM on length-matched reference VM. Slope is dimensionless; intercept and mean signed test-minus-reference bias are in g. Scale-factor error is slope minus one; multiply it by 100 for percentage reporting. Absolute VM bias is the absolute value of the stage-mean signed difference, not the mean absolute paired difference.

VM integral non-linearity

100 times the maximum absolute fitted residual divided by \sqrt{3}F, where F is the test-axis peak-to-peak span in g.

Trial-level composite error

100 times the maximum absolute residual from the pooled response fit divided by \sqrt{3}F/2. This denominator differs from stage VM integral non-linearity by a factor of two. The implemented normalising span is not the nonnegative VM output range.

Within-stage epoch-mean VM CV

SD of within-stage epoch mean VM divided by their mean. The retained field repeatability_error_cv is a fraction. It is distinct from trial-to-trial VM repeatability CV, defined as 100 times SD divided by mean of stage-mean VM across repeated trials for the same unit, stage and pipeline.

Maximum-axis Allan minimum

Maximum across axes of their individual minimum Allan deviations over the evaluated averaging times; reporting in micro-g requires a factor of one million. This is distinct from the axis-specific curves.

ENMO

Epoch mean of \max(v-1,0). Negative differences are truncated to zero per sample before averaging.

MAD

Epoch mean of |v-\bar{v}|, with \bar{v} defined within the epoch. ENMO and MAD are multiplied by 1000 for default mg output.

Index-based dynamic reference matching is not timestamp correction. No equivalence margin or universal fit-for-purpose decision is embedded in these functions. Report the reference, tested range, rate, filtering, epoch settings, signal calibration state, error normalisation and relevant timing diagnostics with every application.

Quantify signal and timestamp integrity

Description

Report integrity diagnostics without sorting, repairing or removing samples.

Usage

qc_accel_tbl(x)

Arguments

x

Acceleration data frame/tibble with POSIXct time and numeric ax_g, ay_g, az_g in g, or a parser/clip bundle containing data/full and optional meta. The data attribute takes precedence over bundle metadata. For this diagnostic function the table must have exactly time, ax_g, ay_g and az_g in that order. No samples are repaired by input conversion.

Details

The ruleset is named primary-five. The five groups below describe the decoded recording, without exclusion, sorting, interpolation or repair. Finite means neither missing, NaN nor infinite. Rounding tolerances are not introduced into exact equality tests.

1. Data integrity

n_samples counts recorded rows. missing_time counts non-finite timestamps. duplicate_time counts repeated finite timestamps after their first occurrence. backward_time counts negative finite differences between adjacent timestamps. invalid_axis counts non-finite scalar axis values across X, Y and Z, so its denominator is three times the row count rather than the number of rows.

2. Sample timing

Select only finite, strictly positive differences between adjacent recorded timestamps. median_dt_ms is their median, iqr_dt_ms is their interquartile range using R type-7 quartiles, and longest_dt_ms is their maximum, all in milliseconds. IQR requires at least two positive intervals. No positive intervals yields NA. These summaries expose spacing and gaps; they do not count missing samples or establish synchronisation with another recording.

3. Axis-zero proportion

For each axis, zero_x_n/zero_y_n/zero_z_n count exact zero values. finite_x_n/finite_y_n/finite_z_n count finite values independently. Each zero percentage is 100 times its axis zero count divided by its finite count; no finite values gives NA. A single zero axis can be expected at some stationary orientations and is not an automatic failure.

4. Unusual cross-axis patterns

all_zero_samples counts rows with X=Y=Z=0; equal_nonzero_samples counts rows with X=Y=Z and X not zero. Pattern counts require finite XYZ values. Each sequence flag is TRUE if its pattern occurs in at least two adjacent eligible rows: both timestamps and all axes must be finite and the timestamp step must be strictly positive. An invalid row, repeated timestamp or reversal breaks the sequence. No gap-duration limit is imposed. Equal non-zero values may differ between adjacent rows. These sample-level rules adapt the NHANES pattern concepts; they do not reproduce its minute-level algorithm or imply every flagged sample is defective.

5. Near-limit values

limit_g is half the configured symmetric peak-to-peak axis span from acquisition$full_scale_range_g. near_limit_fraction is the fixed screening fraction 0.98. Pool finite scalar observations from all three axes and count those satisfying abs(a) >= 0.98*limit_g as near_limit_n. finite_axis_n is the pooled finite count, and near_limit_pct is 100 times their ratio. Missing/invalid range metadata yields an undefined limit/count and percentage. This is a proximity-to-range screen, not proof of clipping or a calibrated saturation threshold.

The diagnostic thresholds, numerators and denominators are retained with the output so they can be reported. The 0.98 near-limit fraction and pooled-axis denominator are screening conventions; VIM measurement-span terminology does not prescribe that fraction. Stored QC describes only the signal and interval on which it was calculated. Recompute after processing changes or a new clip.

Value

A named list of scalar diagnostics. Counts are sample counts except invalid_axis, near_limit_n and finite_axis_n, which count axis observations. Percentages are on the 0–100 scale.

Implementation

Implemented by qc_accel_tbl in R/m_qc.R. See implementation-guide for the framework and function map.
