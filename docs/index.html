Metronautica

Metronautica: Navigate wearable triaxial accelerometer signals into transparent metrology and reports.

Parse wearable recordings, inspect signal quality, characterise measurement response and extract acceleration features. Developed for a research article under submission; associated analyses and data are in WAM.

Getting started · Recording examples · PDF reference · Browser guide

Processing workflow

Native recordings → Acceleration tibble → Static → Dynamic → Features → Reports. Optional calibration returns to assessment with refreshed QC.

Each assessment can also be called independently. Open the browser guide locally for clickable diagram navigation.

Installation

Install dependencies in R:

install.packages(c("tibble", "dplyr", "data.table", "digest", "jsonlite",
                   "signal", "ggplot2", "ggrepel", "scales"))

Download this repository, then install its source directory from R:

install.packages("path/to/metronautica", repos = NULL, type = "source")

Alternatively, run R CMD INSTALL . from the repository root in a terminal. Optional decoder and plotting packages are listed in Getting Started.

Quick start

Run the installed offline example to inspect QC, calculate ENMO/MAD and see their returned values and settings:

library(metronautica)
example("getting-started", package = "metronautica")

For a native recording:

accel <- parse_raw_auto("path/to/recording.agsd", return = "bundle", qc = TRUE)
accel_meta(accel)$processing$qc
features <- compute_accel_summaries(accel, measures = c("ENMO", "MAD"), epoch_s = 5)
head(features$data_wide)

Worked static and dynamic examples with plots use separately distributed samples. Ordinary package use requires neither WAM nor downloads.

Acceleration tibble

Four columns: time (POSIXct, UTC), ax_g, ay_g, az_g (numeric, g). Attached meta records acquisition settings, provenance and QC; read it with accel_meta(). For already decoded data, construct with as_accel_tbl() and attach diagnostics with attach_qc(). Data contract.

Static characterisation

Select a stationary interval with an explicit start and duration. static_metrology_from_tbl() returns noise, signed 1-g VM offset bias, drift, Allan deviation and plots. Individual outcome functions are also available. Example · Reference · Source.

Dynamic characterisation

Specify test/reference recordings, the excitation schedule and measurement range. clip_dynamic_stages() selects stages; dynamic_metrology_report() returns response slope, signed VM bias, VM integral non-linearity, composite error and plots. Example · Reference · Source.

Feature extraction and visual comparison

compute_accel_summaries() returns epoch features and resolved settings; accel_metric_*() functions provide individual calculations. plot_accel_clip() shows acceleration; plot_processed_metric() shows features. Activity counts use the standalone accel_metric_agcounts(). Feature guide · Reference · Source.

Metrology and feature reports

Retain outcomes with their units, reference, tested range and processing settings. Static results provide summary/meta; dynamic results provide stages/overall/meta; feature results provide data_long/data_wide/settings. Outcome reference.

Optional calibration

Use dm_fit_vm_calibration() and its application helpers when additional VM calibration is warranted. Validate benefit independently, call attach_qc() on the calibrated signal, then repeat the selected assessments. Methods · Refresh QC · Source.
